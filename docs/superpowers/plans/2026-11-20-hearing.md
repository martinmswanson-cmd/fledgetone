# Hearing Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give an agent that can't hear a fuller description of a sound (a "sound report") and pictures of it, for bars of a Fledgetone song and for any audio file, with comparison between two hearings.

**Architecture:** New pure analysis and drawing code in `src/audio/hearing/`, built on the existing maths (`mixAnalysis.ts`, `sampleAnalysis.ts`, `loudness.ts`, `harmonicPercussive.ts`, `drumMeasure.ts`, `fft.ts`). One function, `hearingOf`, turns samples into a report and pictures; the renderer (`src/runtime/render.ts`) calls it for songs and for decoded audio files, and the command line calls it directly for WAV files. `fledgetone listen`, `fledgetone measure` and the agent helper expose it through new options. Nothing runs unless asked for.

**Tech Stack:** TypeScript (app conventions), Node 22 test runner (`node --test scripts/*.test.mjs`), `CompressionStream` for PNG (global in Node 22 and Chromium), playwright-core for the headless render page (already used).

**Spec:** `docs/superpowers/specs/2026-11-20-hearing-design.md`. Read it before starting any task.

## Global Constraints

- No machine-learning model, tagger, embedding or outside service. Signal maths only.
- The report describes; it never scores a sound as good or bad. No word list may contain "good", "bad", "too" or "should".
- No copyrighted music in tests, fixtures or examples: made signals and Fledgetone's own renders only.
- Nothing changes what is rendered. A `listen` without the new options does no new work and returns the same report as before.
- Every addition to `ListenReport` / `ListenComparison` is an optional field.
- No new dependency in the root `package.json` or in `tools/cli/package.json`.
- `src/audio/hearing/` is pure: no DOM, no Web Audio, no store imports (`vite.render.config.ts` refuses `timelineStore`).
- Every new source file starts with a summary comment saying what it is (`scripts/codemap.test.mjs` fails otherwise); after adding or renaming files run `npm run codemap`.
- Sources import each other without a file extension, so a test that imports a file with imports of its own registers the resolve hook at the top of `scripts/loudness.test.mjs` (copy it).
- Plain words in every message a person or agent reads; no em dashes in user-facing text.
- Before each commit: `npx tsc -b`, `npx oxlint src` (2 known warnings, both in `Playhead.tsx`), and the task's own tests. The last task runs the full set in CONTRIBUTING.md, "The checks".
- Changes are noted under `## Unreleased` at the top of `CHANGELOG.md` (create the heading if absent); the version in `package.json` is not bumped.

## Review Focus

Inputs the spec implies and a person will meet; each is pinned by a test in the task named.

1. **A mono file.** The stereo group is absent (`stereo` undefined, `channels: 1`), no stereo picture is made, nothing throws. (Tasks 8, 11)
2. **A very short file** (an 80 ms drum hit). A report comes back with `attack.single` filled, groups that need more audio absent, no `NaN` anywhere, and an overview picture is still drawn. (Tasks 8, 11)
3. **Silence** (all zeros, or empty). `silent: true`, `words` is `['It is silent.']`, `JSON.stringify` of the report contains no `NaN` and no `Infinity`, pictures are drawn blank with axes. (Tasks 8, 11)
4. **Sample rates other than 48 kHz** (22.05, 44.1, 96). Bands above half the sample rate are left out of spectra instead of being reported at the floor; frequencies found are right at every rate. (Tasks 1, 2)
5. **A file that can't be read** (a text file named `.mp3`, a format the browser can't decode, a file over the length limit). The command exits with a plain one-line message naming the file and what can be read; no stack trace. (Task 13)

- Produces, in `frames.ts`:

```ts
export const FLOOR_DB = -120;
export const db = (power: number): number;                       // 10 log10, floored at FLOOR_DB, never NaN
export function midOf(channels: readonly Float32Array[]): Float32Array;          // (L + R) / 2, or a copy of the one channel
export function sideOf(channels: readonly Float32Array[]): Float32Array | null;  // (L - R) / 2; null for one channel
export interface Frames { size: number; hop: number; sampleRate: number; power: Float32Array[] }  // per frame, size / 2 + 1 bins
export function framesOf(x: Float32Array, sampleRate: number, size: number, hop: number): Frames;
export function bandEdges(perOctave: number, sampleRate: number, lo?: number, hi?: number): { centres: number[]; edges: number[] };
export function toBands(power: ArrayLike<number>, sampleRate: number, size: number, edges: readonly number[]): Float64Array;
```

  `framesOf`: Hann window; power scaled so the bins of one frame sum to the mean square of the signal in it (a full-scale sine sums to 0.5). A signal shorter than `size` gives one zero-padded frame; an empty signal gives none. `bandEdges`: defaults 20 Hz to 20 kHz, and no band whose upper edge is above `sampleRate / 2`. `toBands`: linear power per band; a bin is shared between bands in proportion to overlap.

- Produces, in `hearingSignals.mjs` (all return `Float32Array`, sample rate argument last, default 48000): `sine(hz, seconds, peakDb)`, `saw(hz, seconds, peakDb)`, `white(seconds, rmsDb, seed)`, `pink(seconds, rmsDb, seed)`, `am(carrierHz, rateHz, depth, seconds, peakDb)`, `gate(x, rateHz, lowDb)` (square, 50% duty, between 0 dB and `lowDb`), `burst(seconds, decayMs, rampMs, peakDb, seed)` (noise with a linear attack and exponential decay), `at(length, pieces)` (places `[seconds, array]` pieces in silence), `mix(...arrays)`, `gain(x, db)`, `clip(x, ceiling)`, `band(x, loHz, hiHz)` (FFT brick-wall band-pass), and `SR = 48000`. Noise uses a seeded generator so tests repeat.

### Task 2: Tone

**Files:**
- Create: `src/audio/hearing/tone.ts`
- Test: `scripts/hearingTone.test.mjs`

**Interfaces:**
- Consumes: Task 1; from `mixAnalysis.ts`: `bandSpectrum(channels, sampleRate): BandSpectrum & { frames: number }`, `totalBands(s): number[]`, `levelBetween(spectrum, levels, lo, hi): number`, `sumDb(levels): number`, `REGIONS`.
- Produces: `export function toneOf(channels: readonly Float32Array[], sampleRate: number): Tone`

  - `spectrum`: `bandSpectrum`, each level rounded to 0.1 dB.
  - `regions`: each `REGIONS` entry's level against the whole, as `measureAudio` in `tools/cli/src/commands.ts` computes it.
  - `centreHz`: power-weighted mean frequency, 20 Hz to 20 kHz, of mid plus side power (from `framesOf(…, 4096, 2048)` averaged).
  - `tiltDbPerOctave`: least-squares slope of `totalBands` against `log2(freq)`, bands from 50 Hz to 12 kHz.
  - `rolloffHz`: the frequency below which 95% of the power between 20 Hz and 20 kHz lies.
  - `subVsBassDb`: level of 20 to 60 Hz minus level of 60 to 200 Hz.
  - `peaks`: on a 1/24-octave spectrum (frames of 16384, averaged), a band that is a local maximum and stands at least 6 dB over the median of the bands within two thirds of an octave either side; neighbours within a sixth of an octave count as one peak; up to 5, largest `overDb` first; `hz` is the band centre.

### Task 3: Texture

**Files:**
- Create: `src/audio/hearing/texture.ts`
- Test: `scripts/hearingTexture.test.mjs`

**Interfaces:**
- Consumes: Task 1; `harmonicPercussive(input, sampleRate): { percussiveShare: number; … }` from `src/audio/harmonicPercussive.ts`.
- Produces: `export function textureOf(channels: readonly Float32Array[], sampleRate: number): Texture`

  - `flatness`: geometric mean over arithmetic mean of the mid's power in bins from 100 Hz to 10 kHz, per frame (4096, hop 2048), averaged over frames louder than -60 dB.
  - `roughness`: the mid is split into seven octave bands centred 125, 250, 500, 1000, 2000, 4000 and 8000 Hz. In each, the envelope is the rectified band smoothed below 300 Hz, and the band's value is the RMS of the envelope's 20 to 150 Hz part over the envelope's mean. The result is the mean of the bands weighted by their power. A band under -70 dB has no say.
  - `percussiveShare`: from `harmonicPercussive`.
  - `flatTops`: the share of samples lying in runs of 3 or more equal (within 1e-4) samples at a local extreme of at least a quarter of the peak; `levelDb` is the level of the commonest such value. `null` when the share is under 0.001.

**Files:**
- Create: `src/audio/hearing/movement.ts`

**Interfaces:**
- Consumes: Task 1; `bandEnvelope(channels, sampleRate, lo, hi, frameSeconds = 0.02): Float32Array` from `mixAnalysis.ts`.
- Produces:

```ts
export const MOVEMENT_BANDS = { low: [40, 250], mid: [250, 4000], high: [4000, 16000] } as const;
export function noteOf(hz: number, bpm: number): string | undefined;
export function movementOf(channels: readonly Float32Array[], sampleRate: number, tempoBpm?: number): Movement;
```

  - `noteOf`: cycles per beat `hz / (bpm / 60)` within 3% of 0.25, 0.5, 1, 2, 4, 8 gives `'1/1'`, `'1/2'`, `'1/4'`, `'1/8'`, `'1/16'`, `'1/32'`; within 3% of 1.5, 3, 6 gives `'1/4T'`, `'1/8T'`, `'1/16T'`; otherwise `undefined`.
  - `changeDb`: third-octave band levels from frames of 4096 every 0.05 s; the mean, over time and over bands louder than -70 dB, of the absolute change from one frame to the next.
  - `modulations`: for each band, its envelope in dB (20 ms frames, floored at -80), mean removed. The strongest spectral peak between 0.5 and 20 Hz is reported when it holds at least 30% of the envelope's varying power in that range and the depth is at least 2 dB. `depthDb` is the envelope's 90th minus its 10th percentile. `note` is `noteOf(hz, tempoBpm)` when a tempo is given. Bands with no such peak are left out. Under 2 seconds of audio there are none.

### Task 5: Dynamics and attack

**Files:**
- Create: `src/audio/hearing/dynamics.ts`, `src/audio/hearing/attack.ts`
- Test: `scripts/hearingDynamics.test.mjs`

**Interfaces:**
- Consumes: `createLoudnessAnalyser(sampleRate)` (`feed(left, right, n)`, `read(): { integrated, shortTerm, truePeakMax }`) and `shortTermWindowFull(framesFed, sampleRate)` from `src/audio/loudness.ts`, used as `measureAudio` in `tools/cli/src/commands.ts` uses them; `onsetStrength(x, sampleRate)` and `onsetTimes(strength, sampleRate): number[]` from `src/audio/sampleAnalysis.ts`; `frameDb(y, sampleRate, frameMs = 1)`, `fallMs(env, db, frameMs = 1)`, `kPeakDb(x, sampleRate)` from `src/audio/drumMeasure.ts`.
- Produces:

```ts
export function dynamicsOf(channels: readonly Float32Array[], sampleRate: number): Dynamics & { shortTerm: Array<number | null> };
export function attackOf(channels: readonly Float32Array[], sampleRate: number): Attack;
```

  - `shortTerm`: the 3-second loudness read once a second, the first at 3 s (empty under 3 s).
  - `rangeLu`: from `shortTerm`: values under -70 LUFS dropped, then values more than 20 LU under the power mean of the rest dropped, then the 95th minus the 10th percentile. `null` with fewer than 5 values left.
  - A mono signal is fed as one channel (the right channel zeros), as `measureAudio` does.
  - `onsetsPerSecond`: onsets over seconds. `riseMs`: at up to the 32 strongest onsets, the time the 1 ms envelope takes from 10% to 90% of that onset's peak; the median. `null` with no onsets.
  - `single`: filled when there is exactly one onset and the audio is under 2 seconds: `riseMs`, `fall20Ms` (`fallMs(env, 20)`) and `peakDb` (`kPeakDb`). (The spec names the existing kick and snare measures. `measureKick` needs the kick's tail frequency, which a plain audio file doesn't give, so the single hit is measured with the same file's general functions instead.)

### Task 7: Faults

**Files:**
- Create: `src/audio/hearing/faults.ts`
- Test: `scripts/hearingFaults.test.mjs`

**Interfaces:**
- Consumes: Task 1.
- Produces: `export function faultsOf(channels: readonly Float32Array[], sampleRate: number): Fault[]` (ordered by `seconds`, those without a time last; `detail` is one plain sentence without the place, which Task 8 adds).

  **Clicks.** Per channel, on the second difference `d[n] = x[n+1] - 2x[n] + x[n-1]`:
  1. The local scale at `n` is 1.4826 times the median of `|d|` over the 10 ms either side, leaving out the 3 samples either side of `n`.
  2. A candidate is a sample where `|d[n]|` is at least 7 times the local scale and at least 0.003.
  3. It is kept only if the median of `|d|` over samples `n+4` to `n+40` is no more than twice the median over `n-40` to `n-4` (a drum's attack fails this: the sound goes on).
  4. It is kept only if no other candidate at least half its size lies within 30 ms (the corners of a clipped or distorted wave fail this: they repeat).
  Candidates within 3 samples are one click. One fault per click (`kind: 'click'`, `seconds`, `channel` when only one side has it, `value`: the jump's size in dBFS) for the first 20; beyond that one more fault with `seconds: null` and `count`: the number left out.

  **Clipping** (`kind: 'clipping'`): runs of 3 or more samples at or above 0.99 of full scale (`|x| >= 0.99`). One fault with the first run's `seconds`, `count`: the runs, `value`: the peak in dBFS. Flat tops below that are not a fault (Task 3 describes them).

  **DC** (`'dc'`): a channel whose mean is above 0.00316 in size (-50 dBFS); `value`: the offset in dBFS; `seconds: null`.

  **Hum** (`'hum'`): from 1-second frames (1 Hz bins), for 50 and for 60 Hz: the bin within 0.5 Hz stands at least 12 dB over the median of the bins from 5 Hz below to 5 Hz above (itself left out) in at least 90% of the frames, its level varies by less than 3 dB across them, and the same holds at 6 dB for its second or third harmonic. `value`: 50 or 60; `seconds: null`. Needs at least 4 seconds.

  **Silence** (`'silence'`): a run of at least 50 ms of exact zeros in every channel, with sound before and after. `seconds` and `endSeconds`.

  **Channel** (`'channel'`): in a two-channel signal, one channel exactly silent while the other isn't, or one more than 10 dB under the other; `channel`: the quiet side; `seconds: null`.

### Task 9: Comparing two hearings

**Files:**

**Interfaces:**

  - A group is compared when both reports have it and its entry in `versions` matches; otherwise it is in `skipped`, with one note: `` `${group} can't be compared: one of these was measured by an older version and must be measured again from its audio.` `` (or `…: only one of these has it.`).
  - Each measure below gives a difference when `|change| / step >= 1`; `size` is that ratio; the list is sorted by `size`, largest first. Region measures use the spectrum above (level-matched).

| Group | Measure | Change is | Step |
|---|---|---|---|
| tone | each `REGIONS` name | level-matched region level, dB | 1.5 |
| tone | `centre` | octaves, `log2(b / a)` | 0.15 |
| tone | `tilt` | dB an octave | 0.5 |
| tone | `sub against bass` | dB | 2 |
| texture | `flatness`, `roughness`, `percussive share` | plain difference | 0.05, 0.08, 0.1 |
| movement | `change` | dB | 0.3 |
| movement | `low band depth`, `mid band depth`, `high band depth` | dB (a band without a modulation counts as 0) | 2 |
| dynamics | `loudness` | LU | 1 |
| dynamics | `crest`, `range` | dB, LU | 1, 1.5 |
| attack | `onsets a second` | `log2(b / a)` | 0.25 |
| attack | `rise` | `log2(b / a)` | 0.4 |
| stereo | `correlation` | plain difference | 0.1 |
| stereo | `mono loss`, `low end width`, `width: ` + each region | dB | 1, 2, 2 |

  - `words`: `` `${Measure}: ${b} against ${a} (${signed change}).` `` with units as in Task 8, the labels in `notes[0]`: `` `Read as ${labels.b} against ${labels.a}.` ``.
  - A length note is added when the longer is more than 1.5 times the shorter: `` `These are different lengths (0:30 against 3:45): a short loud stretch reads brighter, louder and more squashed than a whole track. Compare like with like.` ``
  - Either report silent: no differences, and the note `One of these is silent.`

  `stretchOf` makes a report of part of a saved one, from `along` alone: the rows whose second lies in `[fromSeconds, toSeconds)` are averaged in power into `tone.spectrum`, from which `regions`, `centreHz` (band centres weighted by power), `tiltDbPerOctave`, `subVsBassDb` and `stereo.width` / `lowSideDb` are computed; `dynamics.lufs` is the power mean of the rows' loudness; `peaks` is empty; every other group and measure is absent or `null`; `settings.stretch = { fromSeconds, toSeconds, fromSaved: true }`; `versions` copied; `words` recomputed.
